## 5.1 Evaluating generative text models

**Loss** - a numerical value that measures how wrong a model's prediction is compared to the actual target value. A success indicator.

**Training losses** - a metric that measures how well a machine learning or deep learning model fits the **training data**.

**Validation losses** -  on validation data, unseen testing data.

### 5.1.1 Using GPT to generate text

3 step process to generate text

1. Tokenizer converts input text into a series of token IDs

2. Model receives the token IDs and generates corresponding logits (vectors representing the probability distribution of each token in the vocabulary).

3. Logits are converted back into token IDs (tokenizer decodes back into text).

Use vocabulary (text bank) to map the **input text to token IDs**. Obtain the seven-dimensional probability row vector (**logit**) for each input to via the **softmax function**. Use **argmax** to find the index position with the highest probability in each row vector. Convert the token IDs at these index position into **predicted text**.

Currently without any evaluation and no way to assess the performance of the model, it generates incoherent text. We can monitor and enhance the model's performance through *loss*.

### 5.1.2 Calculating the text generation loss

We can evaluate the performance/quality of the model by calculating the **text generation loss**. 

We can use this loss to construct a **training function**, used to update the model's weight to improve the generated text. Part of the **text evaluation** implemented is to measure "how far" the generated tokens are from the correct targets. The training function will use these values to adjust the model weights to generate text that is more similar to the correct targers.

Since our compact seven-token vocabulary is smaller compared to the vocabulary used to actually train GPT-2, the random evaluated values will hover around 1/7 compared to 1/50,257.

The goal of training an LLM is to **maximize the likelilhood of the correct token**, ie. increasing the probability of the correct token relative to other tokens. The process of updating the model weights is called **backpropagation**. Which requires a loss function, which calculates the difference between the model's output and the desired output. 

**Cross entropy loss** - negative average log probability loss. Measures the difference between 2 probability distributions eg. true distribution of labels and predicted distribution from models. 

**Perplexity** - used alongside cross entropy to evaluate the performance of models. Provide interpretability on how the uncertainty of a model in predicting the next token eg. tensor(48725.8203) - translate to the model being unsure about which among 48,725 tokens in the vocabulary to generate as the next token.
